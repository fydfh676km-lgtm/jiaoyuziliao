# Premium quality gates

Every Premium task passes these internal quality gates in order: `topic`, `scale`, `content`, `visual`, then `production`. Before the user starts production, missing task information may be confirmed and the page count may be confirmed. After an explicit start command, these gates are internal checks and never user pauses.

At `intake`, invoke `$smartedu-reader` (installed skill: `smartedu-numbered-lesson-reader`) by default when a SmartEdu textbook/lesson can be resolved. Its structured source digest is required input for topic and content review unless the user explicitly skips it or supplies a complete direct `image-deck` contract.

| Gate | Required internal artifact | Checkpoint evidence | Frozen data | Single next action |
|---|---|---|---|---|
| `topic` | Requirements and source-analysis brief; resolve only genuinely missing pre-start information | Task confirmation is present | Theme, audience, teaching objective, product positioning, source facts, stated preferences | Produce the scale proposal. |
| `scale` | Scale proposal with duration, page-count options, reasons, recommendation, and chapter structure; options must obey the single-section cap of 30 pages, or 30–35 pages only when SmartEdu confirms exactly 3 class periods | Task confirmation is present; use confirmed page count when supplied, otherwise calculate a compliant count automatically at start | Duration, page count, chapter structure, applicable page-count cap | Wait for the explicit start command, then produce the page-by-page content blueprint without another confirmation request. |
| `content` | Page-by-page content blueprint plus the exact user-facing outline format `第X页 / 页面标题： / 页面文字：` for every page | Internal content and timing checks pass after start | Page order, page goals, titles, core content, activities/cases, timing | Produce the visual-system and page-by-page visual blueprint internally. |
| `visual` | Visual-system proposal plus one exact six-field visual blueprint for every page: `第X页 / 画面风格： / 添加元素： / 文字字体与重点标注： / 布局排版： / 镜头与光影： / 画面去重与统一约束：`; the six labels are unnumbered, the block has no `页面标题：`, and every value is page-specific | Internal visual and reference-use checks pass after start | Visual direction, palette, typographic hierarchy, layout rules, page layouts, elements, shot/light, differentiation, and design intent | Produce the final delivery manifest internally. |
| `production` | Production manifest listing the default combined PPT页纲+视觉蓝图 Word, lesson-plan Word, and speaker-script Word; an exercise Word, PPTX, PDF, or marketing file only when that specific extra was explicitly requested | Internal manifest and scope checks pass | File list, formats, version scope, production routing, delivery naming | Produce the approved files and verification report. |

Before entering the `visual` gate, apply the Xiaohongshu reference rule unless the user explicitly opts out: use the system default browser unless the user explicitly names another browser, search with the fixed short query `#课题名称 课件ppt` after replacing `课题名称` with the exact lesson/topic title, capture exactly one independent first-viewport screenshot, and use only its abstract visual tendencies in the visual-system proposal. Send that same screenshot exactly once as an additional standalone final-handoff attachment, not as a mid-process approval request. A user-supplied reference or persistent-library match does not replace it; skip only on explicit opt-out and record that reason.

## Verification after production

The rows above are internal quality gates, not a sequence of mid-process user approvals. Before any final-deliverable claim, apply the authoritative two-group verification predicate in [`deliverables.md`](deliverables.md), including: source-to-outline/script/lesson-plan coverage, exact outline and visual-blueprint fields, one-to-one page correspondence, the five speaker-script fields per page, the scan for `课时` variants, rendered Word inspection, and valid DOCX-package checks. For the lesson-plan Word, also apply every check in [`teaching-plan-standard.md`](teaching-plan-standard.md), including required section order, detailed process fields, visible substantive emphasis, and the lesson-specific three-layer board plus generation order. Apply the complete `references/wps-safe.md` checklist whenever an optional PPTX is requested. The mandatory format-contract verdict covers the three default Word files. An exercise package, PPTX, PDF, or Xiaohongshu notes are checked only when the specific extra was explicitly requested. For an exercise package, apply `exercise-package.md` and verify question/answer numbering, source support, objective/key-point/difficulty coverage, answer determinacy, scoring points for open responses, cross-file consistency, the `课时` scan, valid DOCX packaging, and rendered layout. The complete cross-file matrix verdict must pass topic, audience, duration, page order, learning objectives, terminology, activity timing, product claims, and source coverage; add WPS-safe status when PPTX is requested. A community PPT adapter is optional: route through available installed capabilities without changing frozen contracts.

If an artifact fails its format contract or cross-file check, regenerate only that failed artifact from the frozen contracts. Do not reopen approved decisions, and do not silently change successful sibling artifacts. Repaired artifacts must re-enter their full format-contract checks and then the complete cross-file checks. Any format-contract failure or matrix mismatch keeps the state at `production_approved`, never `verified`; when and only when both verdict groups pass in full, enter `verified` automatically without user approval or acceptance. In the user-facing repair/transition response, explicitly state that user acceptance or feedback is an optional post-verification handoff, not a verification condition.
